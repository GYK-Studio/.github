## Sobre GYK Studio
Somos un equipo full-stack enfocado en convertir ideas en productos útiles.

## Qué construimos
- 🌐 Plataformas web full-stack
- 📱 Apps móviles para Android e iOS
- 🖥️ Herramientas y utilidades de escritorio
- ⚙️ APIs backend y servicios distribuidos
- ☁️ Infraestructura, DevOps y automatización
- 🎮 Proyectos de gaming y experimentales

## Stack tecnológico
- **Frontend Web**: React, Next.js, TypeScript, JavaScript
- **Mobile**: Flutter, Dart, Kotlin, Swift
- **Backend**: Node.js, Python, Java, Go, C#, Rust, PHP
- **Datos y scripting**: SQL, Bash
- **Infra y DevOps**: Docker, Linux, GitHub Actions

## Cómo organizamos los repositorios
- **Proyectos originales**: software creado y mantenido por GYK Studio
- **Forks**: repositorios externos adaptados para fixes, pruebas o contribuciones

> Si GitHub marca un repositorio como “forked from …”, lo tratamos como fork.

## Cómo trabajamos
1. **Descubrir** — identificamos problemas que vale la pena resolver.
2. **Construir** — implementamos, probamos e iteramos rápido.
3. **Revisar** — validamos comportamiento, calidad y diseño.
4. **Publicar** — lanzamos, monitoreamos y mejoramos.

## Contribuir
Abre un issue o pull request cuando el repositorio destino acepte contribuciones.

Flujo básico:
1. Fork
2. Crear rama
3. Commit de cambios
4. Abrir pull request

Prefijos comunes de commit:
- `feat` nueva funcionalidad
- `fix` corrección de error
- `docs` documentación
- `refactor` refactorización
- `test` pruebas
- `chore` mantenimiento

## Qué vamos a mejorar y agregar
- Estandarizar documentación base por repositorio (`README`, setup y uso rápido).
- Incluir badges de estado (CI, cobertura o releases) cuando aplique.
- Publicar más ejemplos y plantillas para contribuir con mayor claridad.

## Seguridad
Si encuentras una vulnerabilidad, usa el proceso de seguridad del repositorio y evita publicar datos sensibles en público.
